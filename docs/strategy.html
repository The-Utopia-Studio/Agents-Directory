01

The reframe

Today the directory is a catalog — a well-built card wall over a list of agents. That's the right v1. But the thing it's cataloguing is a fleet that should be getting better over time, and a catalog can't make that happen on its own.

Your own ai-native thesis says the moat is “the loop, not the tool” — the compounding system that turns work into better memory and sharper signal. A shelf lists agents; it closes no loop. Nothing an agent does flows back into the directory, and nothing in the directory flows back into an agent to make it better. That gap is the same one you named: the builds are one-shot.

The objective isn't to list agents. It's to become the control plane where the fleet compounds — where goals, skills, tools and context are shared, and eval feeds iteration.

Shelf (today)

  • · Hardcoded list, resets on reload
  • · Eval is a free-text note
  • · Requests & agents disconnected
  • · Skills & tools are loose strings
  • · Builds are one-shot

Loop (target)

  • → Persistent source of truth
  • → Structured, trended eval history
  • → Request → ship → catalogue lifecycle
  • → Skills/tools reusable & countable
  • → Eval → propose → human approves → new version

03

The schema is the product

An agent is only ever as good as four things. The record should be built around them explicitly — so an agent's page becomes a spec you could hand to a builder or a build-agent to regenerate it, and skills & tools become first-class and countable.

① GOALS

What good looks like

The single outcome, the measurable signals of success, and the must-nots.

objective · successCriteria[] · guardrails[]
② SKILLS

Repeatable procedures

References into a shared skills library — assembled, not written from scratch each time.

skills[] → SKILL.md refs
③ TOOLS

What it can act on

MCPs, integrations, APIs — with identity and permissions, not a loose string.

tools[] · type · permissions
④ CONTEXT

What it draws on

Memory, knowledge, data sources — the most proprietary part per your framing.

context[] · source · refresh

Plus the machinery that makes the loop possible — versioned eval history and a human-approvable improvement:

// an agent record, organised around the four pillars
goals:    { objective, successCriteria[], guardrails[] }
skills:   [ { id, source: SKILL.md ref } ]
tools:    [ { id, type: mcp|api|integration, permissions } ]
context:  [ { source, type: memory|doc|dataset, refresh } ]
runtime:  { platform, model, version, changelog[] }
eval:     [ { date, score, status, notes, by, traceUrl } ]  // append-only history
proposedImprovement: { source: "GEPA"|"human", summary, status }  // the loop hook

This is already live in the prototype — the record, the forms, the detail view, the fleet-health strip, and eval-as-history are all rebuilt around these pillars.

04

The loop — killing the one-shot build

The fix for one-shot builds is to make the directory the substrate for a closed loop. 2026 shipped the missing piece: reflective optimisers (GEPA, Hermes self-evolution) that read failing traces and propose targeted prompt / skill / tool-description fixes for ~$2–10 a run. The human stays in the loop as the approver of each version, not the author of each prompt.

The prototype already exercises the human end of this: an agent can carry a proposed improvement; the owner approves it to cut a new version (logged to changelog) or rejects it. In production, that proposal is written by a GEPA job reading Langfuse traces — first target: Bio Generator, already flagged for inconsistent voice-matching.

Your curated skills plug in here: stored as portable SKILL.md folders, referenced by each agent's skills[]. The Skills tab then shows which agents use each skill — and reuse count becomes a headline metric. A skill used by five agents is leverage; one used by zero is dead weight to prune.

06

Sequence

Each step self-justifies and sets up the next — the same “incremental, each self-justifying” move from your ai-native start section.

Schema around the four pillars done in prototype

Goals / skills / tools / context + versioned eval history, live in the app. Highest-leverage, self-contained.

Persistence + lifecycle done in prototype

Local store so nothing resets; Requests → Agents wired so a shipped request becomes a catalogued agent.

Wire observability next

Langfuse tracing behind the agents; eval rows link to real traces. Move the store to Supabase for multi-user.

Turn on the loop next

A GEPA job reads traces for one weak agent and writes a real proposedImprovement. Human approves. Watch fleet health move.

Two-sided directory + factory v2 · v3

Fellows-facing provisioning, then build-and-deploy from within the OS — assembled from existing skills, tools, and context, not blank-page prompts.
