# Agents Directory — Agent Detail Page UI Audit

Audited signed-in at agents-inventory.vercel.app, 4 Aug 2026. Pages reviewed: A7 (Biocraft single-shot draft, including a full "A · Check coverage" run to see the score results view) and A8 (UX&QA Agent). List view excluded per brief.

**Diagnosis in one sentence:** the page has one type size for everything, one narrow column for everything, and one volume level for everything — every caveat is shouted at body-text size in the main flow, so the honest statements compete with the content instead of annotating it. Almost every fix below is the same move: demote the caveat to a chip, a caption, or a tooltip; promote the data.

---

## Prioritised fixes, worst first

### P1 · The scores are buried under three stacked warnings, five dropdowns, and a legend

**What's there now (in order, before you see a number):** the MECHANICAL CHECKS header with a run-on caveat ("not an eval score · does not feed fleet health · not written to evalHistory"), a 3-line inventory list, five labelled dropdown groups (GOLDEN CASE / SCORE VERSION / LEFT / RIGHT / RULER), six buttons, a legend paragraph decoding the buttons, then — after you click — three stacked callout boxes ("Outputs: canned fixtures", "Not comparable — the check set changed…", "Experiment A · check coverage · Same output…"), and only then the two score cards. Below them: "Comparable quality number: refused (null)" (a raw null shown to users), a 9-row wide table, and a status-changes list.

**The fix — headline cards first, everything else demoted:**

```
┌──────────────────────┐   ┌──────────┐   ┌──────────────────────┐
│ v5 · singleshot-v5   │   │  Δ −8.3  │   │ v6 · singleshot-v6   │
│                      │   │  check   │   │                      │
│        33.3          │   │  score   │   │         25           │
│  mechanical check    │   └──────────┘   │  mechanical check    │
│  passed 2 · failed 4 │                  │  passed 2 · failed 6 │
└──────────────────────┘                  └──────────────────────┘
   v6's checks caught 2 more issues on the same output —
   stronger coverage, not worse quality.

   Experiment A · canned outputs · coverage, not quality ⓘ
   ▸ Show all 9 checks        ▸ 4 checks changed status
```

Card anatomy: version label as eyebrow (short "v5"/"v6", full artifact name in small type beside it), the number at 48–64px, unit label under it, pass/fail as small meta. The delta sits **between** the cards, not attached to one, so it reads as a relationship, not a grade.

**Handling lower-is-sometimes-better — three rules:**

1. **Colour and glyphs are direction-neutral for coverage comparisons.** No green/red on the cards or the delta, no ▲/▼ arrows. Delta chip in a neutral accent (the page's slate/orange ink, not a semantic colour). Reserve green/red strictly for pass/fail cells inside the detail table, where the meaning is unambiguous.
2. **Translate the headline into a metric whose intuitive direction is correct.** For Experiment A, the meaningful fact isn't "25 < 33.3" — it's "the new check set caught more issues on identical output." Lead the interpretation line with detections ("caught 4 → 6"), where *more genuinely is stronger*. The raw scores stay on the cards as the canonical numbers; the sentence beneath tells you which way to read them. (The current UI already has the perfect sentence — "stronger coverage, not worse quality" — it's just below the fold in grey. Promote it to the card group's subtitle.)
3. **Make direction a property of the experiment type, not the component.** The same card component renders two semantics: `coverage` (neutral, no arrows, interpretation line mandatory) and `quality` (Experiment B live, where higher *is* better and conventional up/down treatment is allowed). Never let a quality-styled card render coverage data.

**The three stacked callouts collapse into one caption line** under the cards: `Experiment A · canned outputs · coverage, not quality ⓘ` — with the full three sentences in the ⓘ tooltip. Each fact survives: "canned fixtures" is already duplicated as "output source: canned" *on the cards themselves*, so the callout was saying it twice.

**"Comparable quality number: refused (null)"** — never surface a raw null. Render a third, muted tile: `Quality delta — · not comparable (check set changed)`. This is the honest claim turned into a data display instead of a warning paragraph. The fact is *more* visible this way, because it occupies the slot where a naive reader would look for a quality number.

**The table** goes behind `▸ Show all 9 checks`, collapsed by default. The 4-item "check status changes" list is the actual signal — make it the visible summary (`4 checks changed: 1 newly passing, 2 newly failing, 1 retired`), table as reference. `pass · historical` needs a tooltip — it's unexplained jargon right now.

**Persist the last result.** Currently the scores exist only after pressing a button, per visit. The most important numbers on the page should be rendered from the last stored run when you land, with a "re-run" affordance — that alone un-buries them more than any styling.

### P2 · The eval lock is stated three times, once in 26-word ALL CAPS

A7 and A8 both render, within one screen: the caps sentence ("MANUAL EVAL LOGGING STAYS LOCKED DURING THE PILOT BECAUSE…"), a "Not evaluated" badge, and an empty-state box repeating the identical sentence in sentence case. Three artifacts, one fact.

**Fix — one state, three sizes of the same fact:**

- Badge (always visible): `Not evaluated · logging locked (pilot)`
- One caption line under it: *Manual eval logging is locked during the pilot.* `Why? ⌄`
- The "Why?" disclosure (or tooltip) carries the full governed-score/fleet-health/evidence-link reason, verbatim.

Delete the empty-state box entirely; delete the caps rendering entirely. The claim stays permanently on screen (the badge), the full reason stays one click away, and nothing is shouted. **Rule to adopt globally: uppercase + letterspacing is a label treatment, legal for ≤3 words ("GUARDRAILS", "INPUTS"), never for a sentence.** A 26-word caps sentence is the typographic equivalent of holding the caps key through a paragraph — it reads as an error state and slows scanning ~10–15% besides.

The greyed "Log eval" link should also visibly *be* disabled (lock glyph, disabled styling, tooltip = the same "Why?" content) rather than a grey link that looks like a rendering mistake.

### P3 · Reference material is always fully expanded (A8: 17 guardrails ≈ a full screen)

Guardrails, success criteria, the 10-step SOP, and inputs/outputs are read-once reference; you re-read them when something goes wrong, not every visit. On A8 they consume roughly two viewports before you reach eval status.

**Collapse rule — visible by default:**
- Name, description, badges/owner, status
- USE THIS AGENT (the primary action)
- Goal sentence + WHEN TO USE (this is the decision-making text — keep it open, it's 2 lines)
- Eval status line (P2 badge) and last mechanical-check headline cards (P1)
- Skills/tools/context chips (they're compact — fine as is)
- Message-the-owner button

**Collapsed by default, count in the header:**
- `Guardrails (17) ⌄` — show the first 3 with a "Show all 17"; the count itself is informative
- `Success criteria (5) ⌄`
- `SOP — 10 steps ⌄`
- `Inputs (6) · Outputs (6) ⌄`
- `Governed identity ⌄` and `Technical details ⌄`

Remember open/closed state per user if cheap; otherwise collapsed-by-default is right for all of these.

### P4 · Six buttons in internal shorthand, two of which spend money

"Score version (canned)", "Score version (live · paid)", "A · Check coverage", "B · Quality plumbing", "B · Output quality (live · paid)", "Preview comparability" — plus five dropdown groups and a legend paragraph you must read to know what A and B mean. This is a debug panel wearing a toolbar's clothes.

**Fix — two tasks, one menu each, self-describing options:**

- **Score a version** → one button opening a small menu: `With canned output (free)` / `With a live run ($)`.
- **Compare two versions** → version pickers (Left/Right stay, relabelled "Baseline / Candidate") + one menu:
  - `Check coverage — same output, different checks (free)`
  - `Quality plumbing — pipeline test, canned (free)`
  - `Output quality — two live runs + ruler ($)`
- "Preview comparability" becomes automatic: the moment two versions are picked, show the comparability verdict inline ("Check sets differ — coverage comparison only") *before* any button is pressed. It's a validation, not a task.

Kill the A/B letters everywhere (they're internal experiment names), kill the legend paragraph (each menu row carries its own one-line description — same words, relocated to the point of choice). Paid options get a `$` chip and keep the existing confirm step; that's the right pattern, it just needs to be visually distinct *before* the click too. Same treatment for the `hosted-run + download-install` monospace pill in USE THIS AGENT — internal enum values leaking into UI copy ("Run hosted, or download and install").

### P5 · "AGENT A7 · vbiocraft-singleshot-v6" — two version concepts concatenated

The header jams a "v" prefix onto an artifact *name* that already ends in "-v6", producing "vbiocraft-singleshot-v6". A8 shows the other concept ("v0.1.0"). These are different things: a catalog/semver version and an artifact identifier.

**Fix:** header shows `Agent A7 · v6` (or just the agent name + status chip). The full artifact id `biocraft-singleshot-v6` lives in Governed Identity, labelled: **Catalog version:** 0.1.0 / **Artifact:** biocraft-singleshot-v6. Rule: never string-prefix "v" onto anything that isn't a bare number.

### P6 · 64-char SHA-256 inline (twice), 40-char commit inline

A7 prints the full digest in the USE THIS AGENT box *and again* in Governed Identity. A8 runs a full commit hash into a sentence next to the Copy button.

**Fix:** everywhere a digest appears in flowing content: `sha256 a8c08f4e ⧉` — first 8 chars, copy button copies the full value, tooltip shows it. The full digest may stay spelled out in exactly one place (Governed Identity, a key-value block where long monospace belongs). Verification honesty is untouched — the pin is still displayed, still copyable, still checkable; it just stops being a 64-character wall in a sentence. Commits: 7 chars + copy, same rule.

### P7 · The governance banner repeats on every page

"Convex governs this catalog record…" is a 3-line box at the top of *both* detail pages (and its sibling paragraph tops the list view). Every page also already carries a "Governed in Convex" badge — the banner is the badge, verbose.

**Fix:** delete the banner; move its text into the existing badge as a popover (click/hover the badge → full paragraph). The claim stays on every page, above the fold, in two words, with the full statement one interaction away. The "Approved is not applied" family of statements gets the same treatment wherever it appears: encode it in the status chip itself — `Approved · not yet applied` — so the distinction is carried by the data label rather than a standing disclaimer.

## Spacing & density recommendations

The squish is mostly structural, not padding-value tuning:

1. **The page wastes half the viewport.** Content is one ~770px column in a 1500px window, so the page is twice as long as it needs to be and *feels* cramped despite empty space. Move to a two-column layout: main content left (~2/3 — description, use, goals, guardrails, checks); a metadata rail right (~1/3 — owner, status, governed identity, technical details, eval badge, message button). This alone roughly halves scroll length and gives the key-value material a natural home.
2. **Flatten the type hierarchy problem.** There are ~12 section headers per page, all the same size, all caps, all grey — so nothing outranks anything. Three levels: page title (as now) → section headers in sentence case at ~18px semibold → caps micro-eyebrows (≤3 words) only inside cards. If everything is a heading, nothing is.
3. **Un-nest the boxes.** Success criteria/guardrails are bordered cards inside the bordered GOALS card inside the page. Each border eats ~32px of width and adds visual weight. One level of containment max; use hairline dividers or whitespace between sections, borders only for interactive/state surfaces (score cards, callouts).
4. **Bullet columns are too narrow for their content.** The two-column criteria/guardrails cards wrap at ~45 characters with tight leading — that's the "squished" feeling. When expanded (post-P3), give guardrails a single column at full content width, or two columns with a ≥32px gutter and line-height ≥1.5. And humanize the camelCase identifiers: `dedicatedTestAccountsOrAuthenticatedBrowserSession` currently orphans its bullet onto its own line — display "Dedicated test accounts (or authenticated browser session)" with the identifier as a `code` hint or tooltip for API users.
5. **Vertical rhythm:** a consistent scale — 48px between top-level sections, 16px heading-to-content, 8–12px between bullets — instead of the current near-uniform gaps that make section boundaries invisible. The EVAL & OBSERVABILITY header row also crams the caps sentence into a narrow third column next to "Log eval"; after P2 that row becomes a heading + badge and the problem disappears.

## Admin view vs. simple view — yes, split it

The team feedback is right, and the audit explains why: this page serves two jobs. A fellow deciding *"should I use this agent and how?"* needs ~8 things. A maintainer governing the fleet needs the other ~30. Today both audiences get all 38.

Recommended MVP shape: **one page, two tabs** (cheaper than two routes, no data-model change):

**Overview (default, everyone):** name, one-line description, status chips (`Experimental`, `Not evaluated · logging locked ⓘ`), owner + message button, When to use, one primary action (Run / Download / Copy brief), Guardrails collapsed with count, SOP collapsed. Zero digests, zero experiment tooling, zero governance prose beyond the chips. This fits in one viewport.

**Maintainer tab (or role-gated):** mechanical checks lab (P1 cards + task menus + table), Governed Identity (full digests live here), Technical details, Propose improvement / Log eval, the eval-lock "Why?" content, comparability tooling.

The honesty constraint is satisfied because the Overview still carries the load-bearing claims as chips — "Not evaluated", "logging locked", "Governed in Convex", "not an eval score" (on any score shown) — it just doesn't carry their *paragraphs*. Do the P1–P7 fixes first regardless: the Maintainer tab should be the cleaned-up version of this page, not a place to sweep the current one.
